## 4. Required Data Structures and Algorithms

Implement these data structures manually in C++ where applicable. Do not simply replace the required implementations with STL containers and claim the DSA implementation is complete.

### A. Singly linked list — Disaster reports
Store and manage disaster reports.

Operations:
- Insert a report.
- Display reports.
- Search by ID.
- Update report details and status.
- Retrieve reports for dashboard statistics.

### B. Binary heap — Priority queue
Prioritize emergencies according to a documented, configurable urgency policy.

Consider:
- Immediate threat to life.
- Emergency severity.
- People requiring immediate rescue.
- Waiting time.
- Arrival order as a tie-breaker.

Use a clearly documented scoring or priority system. Critical emergencies must be eligible for escalation. The number of people affected alone must not determine priority.

The priority queue must be implemented as a binary heap, not merely described as one.

### C. Queue — Dispatch management
Use a manually implemented queue to manage pending dispatch operations or eligible team scheduling.

Ensure the dispatch process respects the priority queue's ranking. Do not accidentally process all requests strictly in FIFO order when priority ranking should apply.

### D. Linked list — Resource inventory
Maintain dynamically addable resource types and their available quantities.

Operations:
- Add a resource.
- Replenish stock.
- View inventory.
- Allocate resources.
- Record shortages.
- Prevent allocation beyond available stock.
- Return reusable resources when appropriate.

### E. Graph using an adjacency list — Road network
Represent rescue stations, affected locations, and roads.

Each road should include:
- Source and destination.
- Estimated travel time or distance.
- Blocked/unblocked status.

Support adding locations, adding roads, editing road information, and blocking or reopening roads.

### F. BFS
Implement breadth-first search to explore reachable locations or find a path in an unweighted graph.

### G. DFS
Implement depth-first search to explore reachable locations and report the traversal order.

### H. Dijkstra's algorithm
Implement a shortest-path algorithm for non-negative road travel-time weights. Exclude blocked roads from route calculations and report when no route exists.

### I. Stack — Operation history
Maintain recent administrative and operational actions using a manually implemented stack.

Display the most recent actions first. Record meaningful events such as report registration, team assignment, resource allocation, road changes, and rescue completion.

Do not provide a stack-operation teaching animation or internal stack visualization.

### J. Searching and sorting
Implement searching for reports, teams, resources, and locations. Include useful sorting such as reports by urgency, waiting time, or affected population.

Add a doubly linked list for navigating rescue history in both directions if practical.

Include appropriate comments explaining the C++ implementations so they can be presented during a college viva.

### Module 8: Rescue Assignment and Status Tracking

3. Calculate routes from eligible team locations.
4. Compare estimated travel times.
5. Check required resource availability.
